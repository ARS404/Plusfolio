# Доступ и приглашения

Сервер проверяет активность аккаунта, набор ролей, действие и область конкретного объекта. У пользователя может быть несколько ролей. Права объединяются: учитель + аналитик редактирует только свои преподавательские кружки и читает остальные только в пределах аналитических тегов. Приглашение от аналитика не расширяет свою область за счёт чужой роли. Эти проверки обязательны для страниц, API, поиска, аналитики и экспорта.

## Матрица прав

| Действие | Школьник | Учитель | Аналитик | Администратор |
| --- | --- | --- | --- | --- |
| Главная | Свои кружки | Кружки, которые ведёт | Кружки по разрешённым тегам | Все кружки |
| Создать кружок | Нет | Сейчас нет; отдельное будущее разрешение | Нет | Да, в том числе пустой |
| Читать условия | Свои кружки и личная история | Свои кружки + опубликованный банк | Выданные задачи доступных кружков | Любые |
| Читать решения | Только разобранные задачи с включённым показом в своём текущем кружке | Опубликованный банк и свои черновики | Все решения в доступном ему срезе | Любые |
| Читать результаты | Персональные отметки всего своего кружка | Свои кружки и их разрешённые пары | В доступном срезе | Любые |
| Добавлять задачи/листки | Нет | Да, свои черновики и публикации | Нет | Да |
| Изменять опубликованный материал | Нет | Нет, создаётся копия | Нет | Нет, создаётся копия |
| Вести три справочника тегов | Нет | Нет | Нет | Да |
| Выбрать теги нового материала | Нет | Готовые теги соответствующего типа | Нет | Да |
| Читать общий каталог тем | Да, без закрытых материалов и счётчиков | Да | Да, без чужих материалов и счётчиков | Да |
| Управлять деревом тем | Нет | Нет | Нет | Да |
| Выбрать темы нового материала | Нет | Одна или несколько готовых активных тем | Нет | Да |
| Назначать теги кружков и область аналитиков | Нет | Нет | Нет | Да |
| Менять описание и географию кружка | Нет | Свои кружки | Нет | Любой |
| Выдавать листки | Нет | Свои кружки | Нет | Любой |
| Добавить/убрать школьника по email | Нет | Свои кружки | Нет, кроме приглашений ниже | Да |
| Изменять решённость | Нет | Текущий школьник и выданная задача своего кружка | Нет | Да |
| Отметить разбор | Нет | Задача, выданная своему кружку | Нет | Да |
| Показать решение школьникам | Нет | Разобранная задача своего кружка | Нет | Разобранная задача любого кружка |
| Обычные инвайты | Нет | Школьники в свои кружки | Учителя/школьники в доступные существующие кружки | Аналитики, учителя, школьники |
| Добавить администратора | Нет | Нет | Нет | Да, отдельной операцией |
| Отчёты/экспорт | Личный срез | Свои кружки | Разрешённый срез | Все данные |
| Аудит | Собственные результаты без закрытых источников | Доступные учебные объекты | Доступные учебные объекты | Полный журнал |

Опубликованная неизменяемость — правило целостности, а не недостаток административных прав. Администратор может архивировать материал, создавать замену, менять доступ и выполнять предусмотренное удаление персональных данных, но не переписывает смысл старых выдач.

Текущий преподаватель читает исторические результаты своего кружка, но исправляет глобальные результаты только текущих школьников. Исправления по выбывшим предлагает выполнять администратору. Закрытые кружки, преподаватели и остальные результаты школьника не раскрываются через общий факт решения.

У кружка может быть несколько действующих преподавателей одновременно. Каждый получает одинаковые учебные права через свою активную `CircleTeacher`; отдельной роли главного преподавателя нет. Отзыв связи одного учителя не затрагивает доступ остальных. Повторное назначение уже действующего преподавателя в тот же кружок не создаёт дубликат связи.

## Теги и доступ аналитика

Существуют три независимых справочника: задачи, листки, кружки. Администратор создаёт, переименовывает и архивирует определения. Учитель выбирает активные готовые теги своих задач и листков до публикации. Назначение тегов кружка и разрешённых тегов аналитику — только административная операция.

Аналитик получает чтение кружка при совпадении хотя бы одного разрешённого тега кружка. При отсутствии grants список пуст. Теги задач и листков не выдают доступ. Переименование тега не меняет область, а снятие grant или тега кружка отзывает её на следующем запросе. Фильтры отчёта могут только сужать разрешённый срез.

## Темы задач и листков

Дерево тем общее для задач и листков и отделено от трёх справочников тегов. Администратор создаёт, переименовывает, переносит и архивирует узлы; учитель выбирает готовые активные темы своих черновиков. После публикации привязки тем неизменяемы. Изменения дерева сохраняют ID узлов и версию структуры.

Дочерняя «Прочее» создаётся системой под каждым обычным разделом и корнем. Её можно выбрать как тему, но нельзя отдельно переименовать, перенести, удалить, архивировать или дополнить потомками; она следует за родительской веткой.

Темы не расширяют доступ к кружкам или банку. Выбор корневого раздела в поиске сначала пересекается с разрешёнными материалами; счётчики и подсказки по задачам не раскрывают недоступные объекты. Правила дерева и наследования фильтра описаны в [темах](topics.md).

## Управление школьниками по email

1. Учитель выбирает свой кружок и вводит точный email регистрации.
2. Существующий активный аккаунт школьника добавляется сразу: открывается период участия, создаётся аудит. Новое согласие школьника на вступление не требуется.
3. Если такого аккаунта нет, предлагается инвайт. До принятия он виден только в приглашениях, а не в составе и аналитических знаменателях.
4. Повторное добавление уже активного участника возвращает его текущее участие. Email другой роли не преобразует пользователя в школьника.
5. Удаление по email закрывает период и отзывает незавершённое приглашение в этот же кружок. Другие кружки, аккаунт и глобальные результаты сохраняются.

Глобальных списков детей, поиска по части email и подсказок чужих адресов нет. Действие по точному адресу имеет ограничения частоты и аудит, чтобы не превращать его в массовый поиск аккаунтов. Email используется как текущий ключ поиска, а связи хранят стабильный ID пользователя; смена email не теряет участие.

Новые участники автоматически получают назначения всех ранее выданных кружку листков при вступлении. Назначения создаются транзакционно вместе с участием; повторное добавление или вступление не дублирует пары школьник × выдача. Неизвестный email сначала должен принять инвайт.

## Обычные приглашения

| Кто приглашает | Кого | Область |
| --- | --- | --- |
| Администратор | Аналитика, учителя, школьника | Существующие кружки или теги кружков |
| Аналитик | Учителя, школьника | Только существующие кружки, которые он сейчас видит |
| Учитель | Школьника | Только свой кружок |
| Школьник | Никого | — |

Сохраняется иерархия администратор → аналитик → учитель → школьник. Она управляет делегацией, а не наследованием всех возможностей: аналитик не редактирует учебные данные. Первого преподавателя нового кружка приглашает администратор; обычные инвайты аналитика позволяют пополнять преподавательский состав уже запущенного доступного кружка.

В MVP приглашение школьника связано с одним кружком. Учителя можно пригласить в несколько доступных существующих кружков, аналитика — на заданные теги кружков. Назначать теги самому кружку через инвайт нельзя.

### Добавление администратора

Добавление администратора — отдельное явно обозначенное действие, которое доступно только действующему администратору. Для существующего аккаунта это контролируемое добавление роли с обработкой членств и аудитом; для нового — специальное административное приглашение с той же защитой одноразовой ссылки.

Это согласованное исключение из запрета приглашать на равную роль. Обычный endpoint инвайтов его не предоставляет, аналитик и учитель не могут подставить роль администратора. Первый администратор создаётся служебной процедурой при первоначальном развёртывании, без публичной регистрации и стандартного пароля.

### Принятие инвайта

Состояния: ожидает → принят / отозван / истёк. Доставка письма учитывается отдельно.

1. Отправитель задаёт email, допустимую роль и область; сервер повторно проверяет все связи.
2. В одной транзакции создаются приглашение и outbox. Предлагаемый срок — 7 суток, настраивается.
3. Письмо содержит индивидуальную ссылку. Открытие GET показывает сводку, но не активирует доступ.
4. Новый пользователь задаёт пароль и принимает приглашение; создаются аккаунт, профиль и участие. Существующий входит под тем же email; профиль не дублируется.
5. Под блокировкой приглашения сервер проверяет срок, отзыв, текущую роль отправителя, его доступ к области и отсутствие конфликтов. Доступ и состояние «принят» фиксируются атомарно.

Инвайт добавляет указанную роль и область к существующему аккаунту после входа получателя и явного принятия. Прежние роли не заменяются. Прямое добавление по email не выдаёт отсутствующую роль незаметно. Если школьник уже в кружке, принятие не создаёт второй активный период. Истёкший или отозванный токен не оживает.

Явная повторная отправка пользователем создаёт новый токен и отзывает старую ссылку. Автоматический retry почтовой доставки использует ту же ссылку. Механизм рассылки, подавление дублей и статусы описаны в [доставке писем](email-delivery.md).

## Вход и защита ответов

Один HTTPS-домен, серверная сессия в HttpOnly/Secure/SameSite cookie, CSRF-защита изменений. Email нормализуется одинаково во всех операциях, без удаления точек и провайдерских преобразований. Пароли обрабатывает штатная аутентификация Django с пользовательской моделью User для email-логина. [Аутентификация Django](https://docs.djangoproject.com/en/5.2/topics/auth/default/).

Предложение для реализации: минимальная длина пароля 12 символов, поддержка длинных паролей и менеджеров, ограничение частоты входа/почты, второй фактор для административных действий. Восстановление пароля не раскрывает существование email; ссылка ограничена по сроку и одноразовая, смена пароля отзывает старые сессии. [OWASP о восстановлении](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).

Закрытое решение не передаётся школьнику в JSON, первоначальной загрузке, поисковом сниппете или вложении. Исключение — преподаватель/администратор явно включил показ разобранной задачи в текущем кружке школьника. Экспорт журнала содержит отметки, без текстов решений. Закрытые учебные ответы не кэшируются совместно через CDN. Токены из URL не пишутся в логи/аналитику, страница принятия не содержит сторонних счётчиков.

Ограничение queryset, проверка действия и контроль связанных полей применяются вместе. Проверка отдельного объекта не заменяет защиту списков или создания связей. [Права в DRF](https://www.django-rest-framework.org/api-guide/permissions/).

## Отзыв доступа и проверки

Отключение аккаунта и смена роли отзывают сессии. Завершение преподавания и участия, снятие тегов/грантов влияют на следующий запрос. Не завершённые инвайты повторно проверяют текущие права отправителя при принятии. Фоновые отчёты и скачивание проверяют права заново; устаревшая аналитическая витрина не может вернуть отозванный доступ.

Перед пилотом проверяются: чужие ID; подмена роли/типа тега; обход неизменяемости через админку; повторное добавление/выбытие по email; два одновременных принятия инвайта; отзыв до принятия; доступ к решениям через все форматы; выдача администратора неадминистратором; запрет создания кружка учителем при выключенном разрешении.

## Показ решения школьникам

`solution_visible` хранится у пары кружок × задача рядом с разбором. По умолчанию false, в том числе у ранее разобранных задач. Менять его могут только действующие редакторы журнала: преподаватели своего кружка и администраторы. Условие для включения — discussed=true. Снятие разбора атомарно сбрасывает показ; повторный разбор сам его не включает. Правило `solution_visible → discussed` также защищено CHECK-ограничением БД.

В журнале и карточке из журнала учитывается именно выбранный кружок: открытие в A не открывает задачу в B. В персональном списке материалов без контекста решение доступно, если оно открыто хотя бы в одном кружке, где школьник сейчас состоит. При выбытии это разрешение пропадает. Преподаватели, аналитики и администраторы сохраняют свои прежние права чтения решений по ролям.

Галочка использует общую версию записи с разбором и аудит. У одной задачи во всех блоках листков кружка одна настройка. При клике карточка загружается заново с проверкой текущих прав, поэтому новое открытие не опирается на старое содержимое журнала. Уже прочитанный человеком текст отозвать невозможно; следующий ответ сервера учитывает скрытие.

### Обязательные данные школьника

Новая регистрация по школьному инвайту и первое добавление роли школьника существующему аккаунту требуют полного ФИО и года окончания 11-го класса (целое число 1900–2200). Отсутствие отчества отмечается явно. Валидация идёт на сервере в транзакции принятия: неуспех не создаёт аккаунт/участие и не расходует приглашение. Для уже зарегистрированного школьника повторный инвайт только добавляет участие. Старые неполные профили сохраняют доступ и получают подсказку дозаполнить данные в кабинете.

Поиск для добавления в кружок по ФИО — отдельный endpoint выбранного кружка. Его редактор может найти активного зарегистрированного школьника по нескольким частям имени, увидеть класс, год и маскированный email, затем добавить по ID. Читатели, аналитики без преподавания и школьники не могут пользоваться поиском. Выдача ограничена 20 совпадениями; пустой/односимвольный запрос не раскрывает список. Полные email не возвращаются; точное добавление по известному email остаётся. Само добавление повторно проверяет текущие права, активность и роль.

## Личные листки: исключение для собственных материалов

Преподаватель, аналитик или администратор может создать личную копию доступного листка. Только автор редактирует свой документ. У школьника без взрослой роли нет личной библиотеки и права копирования или редактирования; выданные материалы он читает в «Моих задачах». Новый листок с нуля создают преподаватель или администратор.

Личные листки доступны автору и администратору. Администратор может просматривать личные листки всех авторов и публиковать текущие версии для общей библиотеки, сохраняя авторство; чужой оригинал он не редактирует. Остальные создают независимую копию. Участники кружка читают выданную им версию по обычным правилам. Доступ к решениям вычисляется независимо от владения копией.

После правок автора общая библиотека показывает предыдущую опубликованную версию до новой публикации администратором. Выданные версии и их права не изменяются.

## Программный доступ

API `/api/v1` и личные токены доступны при наличии роли преподавателя, аналитика или администратора. Совмещённая роль школьника этому не мешает. Аккаунт только с ролью школьника использует браузерный интерфейс: выдача токенов, Bearer и вход в `/api/v1` через cookie-сессию запрещены. Ранее созданные школьные токены отзываются миграцией; снятие последней взрослой роли отзывает действующие токены.
