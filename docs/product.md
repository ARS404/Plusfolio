# Продукт и границы MVP

Plusfolio помогает вести математический кружок и получать отчётность по выданным задачам и результатам школьников. Главная — список доступных кружков; журнал открывается внутри выбранного кружка.

Правила включают все решения пользователя от 21 октября 2026 года. Уже собрана локальная функциональная демка; таблица MVP ниже описывает цель первой размещённой версии. Реализованные возможности и ограничения перечислены в [локальной демке и этапах выпуска](release-roadmap.md).

## Принятые правила

| Область | Решение |
| --- | --- |
| Главный экран | Список доступных кружков для каждой роли |
| Создание кружка | Сейчас только администратор; он же первоначально приглашает преподавателя |
| Пустой кружок | Можно создать без детей, листков и уже принявшего инвайт преподавателя |
| Преподаватели | Несколько преподавателей могут вести один кружок одновременно; все имеют одинаковые права редактирования кружка в рамках роли учителя |
| Состав | Учитель приглашает школьников и в любой момент добавляет/убирает зарегистрированных детей по email |
| Участие | Периоды сохраняются; при выбытии связь закрывается и архивируется |
| Класс школьника | Необязательный год окончания 11-го класса; текущий класс вычисляется по учебному году с 1 сентября. Год общий для всех кружков, меняют администратор и преподаватели школьника |
| Решённость | Только да/нет, общая между всеми кружками школьника |
| Разбор | Только да/нет, отдельно для каждого кружка и задачи |
| Материалы | Опубликованные задачи и листки неизменяемы; учитель может добавлять свои |
| Выдача листка | Только один раз для пары кружок × листок; хранится дата выдачи |
| Теги | Три разных заранее заданных справочника: задачи, листки, кружки |
| Темы | Общее дерево для задач и листков; у каждого опубликованного материала одна или несколько тем |
| Прочее | В каждом разделе, включая корень, одна автоматически создаваемая дочерняя тема «Прочее» без потомков |
| Управление темами | Администратор ведёт дерево, учитель выбирает готовые темы своего черновика; раздел в поиске включает подтемы |
| Управление тегами | Справочники создаёт и меняет администратор; учитель выбирает готовые теги для своих новых материалов; теги кружка назначает администратор |
| Администраторы | Только администратор добавляет другого администратора |
| Школьник | Читает задачи и результаты сдачи всего своего кружка; аналитика только по себе; решения по умолчанию скрыты, преподаватель может открыть разобранные задачи |
| Совмещение ролей | У аккаунта несколько ролей; разрешения объединяются с сохранением области каждой роли |
| Позднее вступление | Все ранее выданные кружку листки назначаются школьнику автоматически |
| Начальный каталог | Копия математического дерева problems.ru, дополненная системной «Прочее» |
| Размещение | Пользователи из России; все рабочие ресурсы и резервные копии в России |
| Отзыв доступа | При выбытии доступ к кружку закрывается, личная история решений остаётся |
| Удаление | Обычное действие — архивация; удаление персональных данных выделено в отдельную процедуру |
| Развитие | Аналитика для преподавателей, аналитиков и кружков; возможность векторного поиска |
| Резервирование | Полные копии сервиса и проверяемая процедура восстановления |

Ни разбор, ни просмотр условия не меняют решённость автоматически. Отсутствие записи решения отображается как «нет»; третьего учебного статуса нет. Состояния «сохраняется» и «ошибка сохранения» относятся только к доставке изменения на сервер.

## Материалы и идентичность задач

Задача содержит название, описание, условие, решение, темы из общего дерева и теги из справочника задач. Листок содержит название, описание, упорядоченные ссылки на задачи, темы из того же дерева и теги из справочника листков. Темы и теги листка выбираются явно, независимо от классификации его задач.

До публикации автор может править черновик. После публикации фиксируются текст, темы, теги и состав. Исправление, включая опечатку, создаёт новый объект с новым ID и необязательной ссылкой «создан на основе». Старые листки продолжают ссылаться на исходную задачу. Отметки решения и разбора на новую задачу автоматически не переносятся.

Чтобы добавить исправленную задачу в опубликованный листок, создаётся новый листок. Администратор также не переписывает опубликованное содержимое на месте; его полный доступ позволяет архивировать ошибочный объект и опубликовать замену. Это правило сохраняет смысл истории результатов.

Дерево тем единое, с одним родителем у каждого узла, кроме технического корня. Одна задача или листок могут относиться к нескольким веткам. Поиск по родителю включает потомков, материал в результате не дублируется. Переименование или перенос темы администратором сохраняет ID; исторические отчёты фиксируют версию дерева. Подробности — в [общем дереве тем](topics.md).

## Основные сценарии

### Запуск кружка

1. Администратор создаёт кружок, задаёт описание, город/регион и выбирает теги кружка из справочника.
2. Администратор отправляет приглашения одному или нескольким преподавателям в этот кружок. До принятия кружок остаётся допустимым пустым объектом; принятие одного инвайта не отменяет остальные.
3. Преподаватель входит по email и паролю; на главной видит свои кружки.
4. В выбранном кружке отправляет инвайты новым школьникам. Участниками они становятся после регистрации и принятия инвайта.
5. Уже зарегистрированного школьника преподаватель добавляет по точному email без нового подтверждения участия со стороны ребёнка.
6. Преподаватель выбирает готовые задачи или добавляет свои, публикует листок и выдаёт его кружку с датой.

Создание кружка учителем в будущем включается отдельным разрешением. Оно не должно давать право назначать теги кружка и расширять доступ аналитиков. Пока разрешение выключено.

### Управление составом по email

Точный email регистрации однозначно находит аккаунт школьника. Повторное добавление в активное участие ничего не дублирует. Если email неизвестен, интерфейс предлагает отправить инвайт; членство до его принятия не создаётся. Если email принадлежит другой роли, роль не меняется автоматически.

Удаление из кружка закрывает текущий период участия и отзывает доступ только к этому кружку. Глобальный аккаунт, участие в других кружках и результаты не удаляются. Повторное вступление открывает новый период. Незавершённый инвайт в тот же кружок при удалении отзывается, чтобы доступ не появился позже.

Список всех зарегистрированных детей преподавателю не показывается: есть действие по конкретному email и состав его кружков. В рассылке допускается пакет адресов с отдельным результатом для каждого получателя; письма индивидуальные, адреса детей не раскрываются другим адресатам.

### Работа с журналом

Внутри кружка преподаватель выбирает выданный листок. Строки — школьники, столбцы — задачи; ячейка меняет глобальные да/нет, отдельная строка — разбор в текущем кружке.

Несколько преподавателей работают с общим составом, выдачами и журналом. У каждого своя действующая связь с кружком, а каждое изменение сохраняет фактического автора. Завершение работы одного преподавателя отзывает только его доступ; права остальных и учебная история сохраняются. Параллельная правка одной отметки проверяется по версии записи.

Одна и та же задача имеет общий результат во всех листках и кружках школьника. Снятие отметки также отражается везде. Параллельные изменения разрешаются по версии записи, каждое изменение имеет автора и время. Источник из чужого кружка не раскрывает его закрытые данные.

### Работа школьника и аналитика

Школьник начинает со списка своих кружков; читает условия, видит персональные отметки всех участников своего текущего кружка и статус разбора. Аналитические сводки доступны только по себе, включая личную историю после выбытия. Самостоятельно менять отметки и отправлять решения в MVP он не может; решения получает только после явного включения показа разобранной задачи в своём кружке.

Аналитик начинает со списка кружков с разрешёнными тегами, читает все доступные в этой области учебные данные, включая решения задач, журналы и аналитику. Учебные данные не редактирует. Он может приглашать учителей и школьников в доступные уже запущенные кружки; первого преподавателя назначает администратор.

## Выдачи и аналитика

Факт выдачи школьнику фиксируется явно. При выдаче листка назначения получают текущие участники. При новом вступлении школьник автоматически получает все прежние листки кружка; дата назначения соответствует вступлению, дата первоначальной выдачи кружку сохраняется отдельно. Повторное вступление не дублирует существующие назначения. Выбытие сохраняет их для истории и знаменателей.

Закрытие задачи P в выбранном срезе:

**100 × число уникальных школьников, которым выдавали P и у которых P решена / число уникальных школьников, которым выдавали P.**

Повторения P в листках и кружках не увеличивают число людей в знаменателе. При пустом знаменателе показывается «нет данных». Выбывшие сохраняются в исторической когорте получателей; фильтр «только текущие участники» задаёт другой срез и явно подписывается.

Текущее закрытие включает ранее решённые задачи. Для оценки новых результатов отдельно считаются подтверждения после первой выдачи; это не доказательство эффекта преподавателя. Показатели, временные срезы и факты для них описаны в [проекте аналитики](analytics.md).

## Этапы и проверки готовности

1. **Локальная демка.** Проверить роли, инвайты в локальном ящике, состав, выдачи, глобальные отметки и независимый разбор.
2. **Отладка механики.** Пройти сценарии вместе с преподавателем, собрать обратную связь, исправить поведение и интерфейс.
3. **Первая размещённая версия.** PostgreSQL, настоящая российская почта, HTTPS, защита, внешние резервные копии и тест нагрузки на 100 кружков / 1 000 задач.
4. **Пилот и обратная связь.** Несколько реальных кружков; проверить занятия, удобство, доставку писем и полное восстановление.
5. **Полноценный релиз.** Пагинация и SQL-аналитика, нагрузочные проверки сотен кружков и десятков тысяч задач; ресурсы увеличиваются по измерениям.

Ключевые проверки: решение общее между двумя кружками; разбор независим; повторная выдача запрещена; удаление участника не меняет исторические знаменатели; теги разных типов не смешиваются; темы общие для задач и листков, дерево без циклов, поиск и метрики веток без дублей; опубликованный материал нельзя изменить; учитель не создаёт кружок и не назначает администратора; школьник не получает закрытое решение; открытие решения требует разбора и действует только в выбранном кружке; почтовый повтор не создаёт второй доступ.

## Оставшиеся уточнения

Подтверждено: школьник видит журнал сдачи всего своего кружка, но аналитику только по себе; аналитик читает в своём срезе всё, включая решения; текущий преподаватель может исправить чужую глобальную отметку для разрешённой пары школьник × задача с аудитом. Несколько ролей объединяют возможности, а область одной роли не расширяется за счёт другой.

Масштаб пилота — несколько кружков. Расчёт первой размещённой версии: 100 кружков и 1 000 задач. Целевой рост — сотни кружков и десятки тысяч задач. Только российское размещение. Домен и доступы провайдеров потребуются перед размещением; бюджет с актуальными тарифами — в [расчёте](hosting-budget.md). Порядок: локальная демка → отладка механики → первая версия и обратная связь → выпуск на целевую мощность.


Списки и выбор кружков фильтруются по городу. Библиотека и выбор задач/листков фильтруются по соответствующим тегам; темы собственных тегов не имеют. В аналитике город, теги задач, теги листков и тема работают совместно в пределах текущего доступа. Фильтр листков журнала действует и на выгрузку.


Подробная аналитика демки включает задачи, полные листки, темы с потомками, индивидуальный прогресс, медиану и распределение по школьникам, результаты кружков и покрытие разбора. Все показатели используют текущую глобальную решённость и разрешённые назначения; дата расчёта указана в интерфейсе. Посещаемость и временная динамика обучения появятся после внедрения соответствующих фактов.
