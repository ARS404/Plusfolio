# Plusfolio 1.0.3

Релиз от 01.11.2026: версия `1.0.3`, статус `released`, неизменяемый тег `v1.0.3`. Сохранённый ниже отчёт описывает этап локальной подготовки; установка выполняется из проверенного релизного коммита и соответствующих ему образов.

## Состав

- Явное обновление выдачи кружка до доступной версии того же листка, изменение даты и защита от конфликтов. Задачи могут добавляться и удаляться; получатели и история отметок сохраняются.
- Четыре итога плюсника по выбранному срезу уникальных задач: решено, доступно для сдачи, не решено и разобрано, всего.
- Галочка «Учитывать разобранные задачи» во всех показателях аналитики. Новая сдача после разбора в соответствующем кружке запрещена; прежние плюсы сохраняются.
- Уборка повторных вычислений и выделений памяти, облегчение выбора версий выдачи, завершение запросов редактора и ограничение TeX-сервиса четырьмя обработчиками при одной сборке.

Подробности — в [истории изменений](../../CHANGELOG.md). Замеры на синтетических локальных данных, ограничения измерений и результаты предыдущей полной регрессии — в [отчёте уборки](../benchmarks/cleanup-2026-11-01.json). Они не являются нагрузочной проверкой сервера.

## Миграция с 1.0.2

Миграция `0019_issue_edit_version` добавляет `WorksheetIssue.version` с начальным значением `1` существующим выдачам. Данные не пересоздаются: UUID и номера, редакции листков, блоки, изображения, нумерация с нуля, исключение задач из плюсника, назначения, плюсы и разборы сохраняются. Применённая миграция не выполняется повторно и не сбрасывает изменённые счётчики версий. Отдельный SQL-скрипт не нужен.

Это проверяется на отдельной тестовой БД переходом `0018 → 0019`: сравниваются все прежние поля учебных сущностей, данные изображений и их связи; отдельно проверяется повторный запуск. Проверка перехода со старого формата листков `0016 → 0019` также сохранена. Зависимости, API `/api/v1` и версии шаблонов TeX относительно 1.0.2 не меняются. Сброс прогретого TeX-кэша не требуется.

## Проверки перед выпуском

```bash
python3 scripts/release.py --check
python3 scripts/release.py --check-tag v1.0.3
.venv/bin/python backend/manage.py makemigrations --check --dry-run
.venv/bin/python backend/manage.py test core.test_release core.test_block_migration core.test_issue_updates core.test_tex_service_limits --noinput
python3 deploy/test_shared_host.py
python3 deploy/test_capacity.py
python3 -m unittest deploy.test_cloud_deploy.ImageTests
(cd frontend && npm test && npm run build)
git diff --check
```

Результаты подготовки сохраняются рядом с этой инструкцией в [машиночитаемом отчёте](1.0.3-checks.json). Локально используется SQLite. Linux/Docker и PostgreSQL необходимо дополнительно проверить в CI перед установкой на рабочий сервер. Имеющиеся четыре PostgreSQL-проверки в полной локальной регрессии пропущены; предупреждение сборки о размере основного JS-файла остаётся.

После проверки изменений выпуск оформляется отдельным коммитом и неизменяемым тегом `v1.0.3`; проверка `--check-tag` сама тег не создаёт. Перед сборкой распространяемых образов рабочее дерево должно быть чистым, чтобы OCI-метки и версия `/healthz` указывали на релизный коммит без `-dirty`.

## Установка после публикации

В существующей папке установки:

```bash
python3 scripts/server.py backup
# Получить и проверить исходники опубликованного v1.0.3.
python3 scripts/server.py update
python3 scripts/server.py version
python3 scripts/server.py check-public
```

Для готовых образов вместо обычного обновления: `python3 scripts/server.py update --release /путь/images-1.0.3.json`. Манифест должен соответствовать версии и архитектуре сервера. Отдельная команда `backup` позволяет заранее убедиться в доступности резервирования; сам `update` создаёт ещё один свежий полный бэкап после остановки пишущих `web`, `mail` и `indexer` этого экземпляра. Контейнер `initialize` применяет миграции до запуска зависимых служб.

После обновления проверьте:

1. `version` возвращает `1.0.3` и ожидаемую Git-ревизию; внешний `check-public` проходит.
2. Прежние выдачи, назначения и отметки видны. Во вкладке «Листки» доступен редактор выдачи и показ разницы состава; отмена не меняет данные.
3. На тестовой выдаче смена редакции обновляет только выбранный кружок. Прежние плюсы для оставшихся задач сохраняются, новые задачи появляются, исключённые исчезают из выбранного среза.
4. Четыре итога журнала соответствуют выбранным задачам; аналитика корректно меняется в обоих положениях галочки учёта разобранных.
5. PDF прежнего и нового листка собирается; доверенные ресурсы TeX сохраняются.

При ошибке бэкапа `update` возобновляет прежние контейнеры без изменения схемы. При ошибке миграции зависимые службы не запускаются: проверьте `python3 scripts/server.py logs initialize`, устраните причину и повторите `update`. Автоматического отката схемы нет. Для восстановления нужен согласованный комплект приложения и БД из бэкапа; не запускайте прежнее приложение поверх частично обновлённой схемы. Ключ `.deploy/backup.key` храните отдельно. [Полная инструкция сервера и восстановления](../server-deploy.md).
