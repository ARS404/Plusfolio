# Plusfolio 1.0.5

Релиз от 07.11.2026: версия `1.0.5`, статус `released`, неизменяемый тег `v1.0.5`. [История изменений](../../CHANGELOG.md), [проверки перед релизным коммитом](1.0.5-checks.json). Публикация тега и установка на сервер выполняются отдельно от локальной подготовки.

## Что изменилось

- Столбцы задач в плюснике имеют ширину 48 px. Под номером виден ID, название показывается при наведении и доступно скринридеру. Полоска прогресса занимает 28 px; числа «решили/получили», исходная нумерация и фильтры сохранены. Размер кнопок номеров (28 px) и плюсов (25 px) не уменьшен.
- Открытое решение отмечается маленьким глазом возле номера. Пояснение доступно при наведении и клавиатурном фокусе. Кнопки PDF/TeX в шапке листка уплотнены.
- Автономный TeX-пакет требует успешно проверенный кэш обоих шаблонов, включая tcolorbox. Экспорт сверяет запись подготовки с текущими исходниками и ресурсами. Хешируются фактические байты ZIP; частичный архив при изменении файлов или превышении лимита удаляется.
- `--prepare` проверяет временную копию ресурсов с `--only-cached`, не дополняя скачанный кэш и не меняя manifest. Сеть нужна только для установки закреплённого официального бинарного файла Tectonic, если он ещё не установлен.
- В серверном образе ресурсы приложения находятся в `/app/tex-runtime`, вне постоянного тома. Старый том больше не скрывает кэш новой версии. Backup берёт ресурсы текущего образа и сохраняет совместимые пути `source/.local/...`.
- Входные ресурсы ограничены 256 МиБ / 4096 файлами и каталогами, запись подготовки — 2 МиБ. ZIP упаковывается порциями до 1 МиБ и выдаётся потоком; хранилище ZIP ограничено 128 МиБ и двумя архивами.
- В тег включено исправление workflow публикации образов, ранее отправленное после `v1.0.4`. Контейнерные фикстуры TeX используют собственные ресурсы при заданном пути ресурсов образа.

## Данные и совместимость с 1.0.4

Новых миграций нет. Последняя миграция — `0019_issue_edit_version`; модели, зависимости, версия API, шаблоны `math-a4-v1/v2` и модель поиска не меняются. Штатный `server.py update` сохраняет volumes и выполняет `migrate --noinput` после свежего бэкапа. Сохраняются все ID, пользователи, кружки, листки и редакции, выдачи, назначения, картинки, плюсы, разборы и открытые решения.

Отдельный SQL-скрипт, повторная выдача листков и удаление кэшей/volumes не требуются. Для контейнерной установки нужны новые образы **application и compiler**: прогрев только старого runtime-тома не обновляет ресурсы образа.

Новый TeX-пакет получает новый `contract_id`. После обновления робот заново скачивает JSON контракта и ZIP в отдельный каталог и использует ID из нового JSON. Нельзя переписывать хеши старого manifest или применять старый `--expected-contract` к новому пакету. [Подготовка и проверка TeX](../tex-preflight.md).

## Проверки и границы измерений

[Отчёт о памяти](../benchmarks/tex-export-memory-2026-11-07.json) разделяет чтение метрик рабочего сервера и локальную проверку экспорта. На сервере прочитаны три набора счётчиков; нагрузка и перезапуски не выполнялись. Локально проверены 48 потоковых скачиваний с параллельностью 8; временный прирост выделений Python составил около 11 МиБ, остаточный — около 31 КиБ. Это не нагрузочный тест сервера и не гарантия всех будущих сценариев.

Проверки перед коммитом:

```bash
python3 scripts/release.py --check
python3 scripts/release.py --check-tag v1.0.5
.venv/bin/python backend/manage.py makemigrations --check --dry-run
.venv/bin/python backend/manage.py migrate --plan
.venv/bin/python backend/manage.py test core --noinput
PYTHONPATH=deploy .venv/bin/python -m unittest deploy.test_shared_host deploy.test_capacity deploy.test_cloud_deploy.ImageTests deploy.test_cloud_deploy.StorageTests deploy.test_downloads
(cd frontend && npm test && npm run build)
git diff --check
```

Полная локальная регрессия использует отдельную SQLite-БД. PostgreSQL, сборка Linux/Docker, HTTPS, SMTP и восстановление настоящего серверного бэкапа проверяются отдельно workflow `Verify server installation`. Локальные проверки не подменяют этот этап.

## Установка после публикации

В чистой папке исходников действующего экземпляра, с отдельно сохранённым `.deploy/backup.key`:

```bash
python3 scripts/server.py backup
git fetch origin --tags
git switch --detach v1.0.5
python3 scripts/server.py update
python3 scripts/server.py version
python3 scripts/server.py check-public
```

Для готовых образов: `python3 scripts/server.py update --release /путь/images-1.0.5.json` с манифестом той же версии и архитектуры. `update` делает дополнительную свежую полную копию после остановки пишущих `web`, `mail` и `indexer`, затем запускает `initialize` и остальные службы. Использовать `up` вместо обновления версии нельзя.

После установки:

1. `version` и `/healthz` сообщают `1.0.5` и ожидаемую ревизию; `check-public` проходит.
2. Прежние выдачи, назначения, плюсы, разборы и настройки показа решений сохранены. Узкие заголовки не перекрываются, названия доступны по наведению, фильтры и прокрутка работают.
3. PDF существующего листка `math-a4-v1` и нового `math-a4-v2` с рамкой, PNG и TikZ собираются.
4. Новые JSON контракта и ZIP совпадают. Два запуска `--prepare` не меняют хеши; сборка условия и решения проходит из распакованного пакета.
5. Новая зашифрованная резервная копия проходит проверку. TeX-ресурсы в ней взяты из текущего образа, пути восстановления прежние.

При ошибке бэкапа `update` отменяет обновление и возобновляет прежние пишущие службы. При сбое новых образов используйте предыдущие образы и сохранённую полную копию по [инструкции восстановления](../server-deploy.md); не удаляйте runtime-том ради TeX-кэша. Миграций 1.0.5 нет, однако восстановление БД всё равно выполняется только из согласованной копии.
