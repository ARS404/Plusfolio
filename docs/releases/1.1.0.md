# Plusfolio 1.1.0

Выпуск от 19.11.2026, тег `v1.1.0`. [История изменений](../../CHANGELOG.md), [проверки выпуска](1.1.0-checks.json).

## Изменения

- Кружок можно перевести в архив и восстановить. Архив доступен для просмотра, изменения журнала, состава и выдач требуют активного кружка. На странице кружков доступны фильтры статуса; в аналитике по умолчанию учитываются все доступные кружки.
- Новые выдачи создаются скрытыми. «Показать школьникам» открывает листок и назначает его текущему составу. Скрытые выдачи доступны взрослым в их области; после вступления школьник получает уже открытые листки.
- На телефоне меню всех ролей сворачивается в портретной и альбомной ориентации. Регистрация включает повтор пароля и кнопку его показа.
- Страница задачи содержит ссылки на использующие её листки библиотеки. Каждая версия листка показывает кружки с текущей выдачей именно этой версии; после замены выдачи ссылки пересчитываются.
- Ускорены пакетные выдачи, приглашения, аналитика, фильтры и дерево тем. Исправлены конкурентный отзыв приглашения и изменение ролей, смена форм редактора и завершение сохранения после закрытия формы.
- Excel записывается потоком, отметки выгрузки читаются итератором. Размер проверяется перед загрузкой карточек и отметок. Общий допуск ограничивает экспорт одной операцией на веб-экземпляр; при занятости возвращается HTTP 429 с `Retry-After`. Скрытые выдачи помечены и содержат прочерки в результатах школьников.
- Обновлены справка сайта для людей и роботов, OpenAPI и инструкции обновления/восстановления. [Условия локальных измерений](../benchmarks/cleanup-2026-11-18.json).

## Переход с 1.0.6

В папке установленного экземпляра после публикации тега выполните:

```bash
git fetch origin tag v1.1.0
git switch --detach v1.1.0
python3 scripts/server.py update
python3 scripts/server.py version
python3 scripts/server.py check-public
```

Для готовых образов используйте `python3 scripts/server.py update --release /путь/images-1.1.0.json` с проверенным манифестом той же версии и архитектуры. Штатный `update` останавливает пишущие службы, создаёт полный бэкап и запускает миграции через `initialize`. Проверьте успешное завершение бэкапа и сохраните доступ к ключу восстановления.

Применяется `0020_issue_visibility`. Уже существующие выдачи получают `visible_to_students=true`, новые — `false`. Миграция сохраняет прежние ID, версии выдач, назначения, материалы, изображения, плюсы и разборы. Повторный запуск сохраняет выбранные значения флага.

Роботам и интеграциям нужно включить отдельное открытие в сценарий выдачи. После `POST /api/v1/circles/{id}/issues` сохраните числовой ID выдачи и `version`, затем для показа школьникам вызовите `POST /api/v1/circles/{id}/issues/{issue_id}/publish` с `{"version":N}`. Прочитайте актуальную справку `GET /api/v1/documentation?audience=robot`. `/api/v1`, `instruction_policy_version` и версия продукта имеют самостоятельные номера.

## Новая БД и восстановление

Для переноса на другой PostgreSQL или сервер используйте проверенный зашифрованный бэкап и отдельный новый экземпляр по [руководству восстановления](../server-deploy.md#восстановление). Восстановите согласованную версию приложения и БД из комплекта, проверьте данные, затем обновите восстановленный экземпляр до 1.1.0 штатным `update`.

`restore-database` проверяет отсутствие `core_user` и отказывается перезаписывать инициализированную БД. Восстановление отзывает прежние сеансы, API-токены и ожидающие приглашения, отменяет неотправленную почту. Учебные данные и видимость выдач из копии 1.1.0 сохраняются. Копия со схемой до `0020` проходит миграцию при последующем обновлении.

## Приёмка и откат

1. Проверьте `version`, `/healthz` и `check-public`; ожидается 1.1.0. Убедитесь, что последняя миграция — `0020_issue_visibility`, повторный запуск миграций завершился без операций.
2. Откройте прежний плюсник под преподавателем и школьником. Сверьте ID выдач, назначения, плюсы, разборы и доступность прежних листков.
3. Подготовьте новую скрытую выдачу. Проверьте отсутствие доступа у школьника, затем откройте её и проверьте назначения текущему составу. Повторное открытие сохраняет результат.
4. Проверьте архивирование/восстановление, фильтры аналитики, ссылки задача → листки и версия листка → кружки.
5. Проверьте мобильное меню, регистрацию, Excel/TSV выбранного среза и справку с `audience=human`/`robot`.
6. Создайте очередной бэкап и проверьте его целостность.

Для возврата к версии до 1.1.0 восстановите согласованный снимок до обновления в новый экземпляр. Обратная миграция удаляет флаг видимости, а старое приложение может открыть подготовленные скрытые листки. При ошибке миграции сохраняйте остановленное состояние прежних пишущих служб до восстановления согласованной пары приложения и данных.

Локальные проверки и ограничения перечислены в `1.1.0-checks.json`. Проверки нативных блокировок PostgreSQL и полного Linux/Docker-обновления требуют рабочего контейнерного стенда.
