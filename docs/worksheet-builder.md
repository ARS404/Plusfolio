# Конструктор листков

Листок — последовательность блоков `problem` и `text`. Нумеруются только задачи; их UUID и глобальные отметки сдачи сохраняются. Начало нумерации выбирается в конструкторе: с 1 (по умолчанию) или с 0. Допустим листок только с теорией: выдача и PDF работают, столбцов сдачи нет. Редактирование создаёт новую неизменяемую версию, уже выданные версии не меняются.

## Редактор

«Текст» и «Задача» вставляют блок в выбранное место. Текст поддерживает обычное оформление, заголовок, определение, теорему, лемму, пример и замечание. Блоки можно сворачивать, перемещать стрелками или за ручку, текстовые — копировать. У каждой задачи есть флажок «В плюсник» (по умолчанию включён). Снятый флажок сохраняет задачу в листке, исходниках и PDF, но исключает её из таблицы сдачи и подсчёта прогресса. Номера остальных задач сохраняются: например, после вводной задачи №0 в плюснике остаются №1, №2 и далее. Темы и теги находятся в отдельном раскрываемом разделе.

Обычное поле принимает текст и формулы `$…$`. Заполненный TeX имеет приоритет в PDF; преамбула не нужна. Новый шаблон `math-a4-v2` предоставляет окружения с рамкой и переносом между страницами:

```tex
\begin{definition}[Инвариант]
Величина, сохраняющаяся при разрешённых преобразованиях.
\end{definition}
```

Аналогично доступны `theorem`, `lemma`, `example`, `remark`. При выборе оформления «Определение» в интерфейсе окружение добавляется автоматически: достаточно ввести его содержимое. TikZ работает в блоках, условиях и решениях; «Пример TikZ» вставляет стартовый рисунок.

«Обновить PDF» собирает текущие поля без сохранения версии. После изменений видна отметка об устаревшем предпросмотре. Проверяйте точную вёрстку TeX и TikZ в PDF: страница листка показывает обычный текст и загруженные картинки.

## Картинки

PNG/JPEG вставляются кнопкой, из буфера или перетаскиванием файла. Один файл — до 2 МиБ, 16 мегапикселей и 8192 пикселей по стороне; анимация не поддерживается. Сервер применяет ориентацию EXIF, сохраняет нормализованный PNG без метаданных и объединяет одинаковые загрузки одного автора. До 20 картинок на часть содержимого, суммарно 50 МиБ на автора. Неиспользованные загрузки старше суток очищаются при следующей загрузке; привязанные к сохранённым материалам не удаляются.

Маркер `\pfimage{UUID}` задаёт положение картинки между абзацами. Ширина — 10–100% строки, выравнивание — `left`, `center`, `right`, подпись необязательна. Если маркер убрали вручную, прикреплённая картинка печатается в конце блока. Кнопка удаления рисунка удаляет его маркеры и привязку из текущего черновика.

Доступ к PNG проверяется сервером при каждом запросе. Картинка решения доступна только тому, кому доступно само решение; в закрытом PDF/ZIP её нет. Изображения хранятся в БД и входят в существующую резервную копию. ZIP проекта содержит исходники, текстовые блоки и PNG. Отдельный `.tex` с рисунками требует папки `assets` из ZIP.

## API и совместимость

`POST /api/v1/materials/worksheet` и обновление документа принимают `blocks`:

```json
{
  "title": "Инварианты",
  "numbering_start": 0,
  "topics": ["UUID_ТЕМЫ"],
  "blocks": [
    {"kind": "text", "style": "definition", "title": "Инвариант", "text": "Сохраняющаяся величина.", "tex": "", "images": []},
    {"kind": "problem", "problem_id": "UUID_ЗАДАЧИ", "include_in_journal": true},
    {"kind": "text", "style": "remark", "title": "", "text": "Подсказка после задачи.", "tex": "", "images": []}
  ]
}
```

`style`: `plain`, `heading`, `definition`, `theorem`, `lemma`, `example`, `remark`. От 1 до 300 блоков; одна задача не повторяется. `numbering_start` — целое 0 или 1. `blocks[].include_in_journal` для задачи — boolean, по умолчанию true; настройка действует на конкретное вхождение в версию листка. Все задачи остаются в `problem_ids` и в выдаче материалов, включая исключённые из плюсника. Копирование и правка метаданных сохраняют настройки; уже выданные версии не меняются. Старое поле `problems: [UUID,…]` создаёт только блоки задач. Если переданы оба поля, порядок задач обязан совпадать. Для существующего смешанного листка изменение только `problems` отклоняется: клиент должен передать полный `blocks`, чтобы сохранить текст.

`POST /api/v1/images` принимает multipart `file` или JSON `{"data":"BASE64"}` и возвращает `id`, `url`, `width_px`, `height_px`, `size`. В текстовом блоке `images` содержит `{"id":"UUID","width":70,"align":"center","caption":"…"}`. Те же массивы называются `statement_images` и `solution_images` в задаче.

`GET /api/v1/images/{id}` возвращает PNG после проверки доступа. `POST /api/v1/worksheets/preview` принимает название, описание, блоки и `solutions`; возвращает PDF без сохранения. Предпросмотр разрешён взрослым ролям (преподаватель, аналитик, администратор), включая read_only токен, до 12 запросов в минуту. Создание изображений требует токен с записью.

В подробном ответе листка есть `blocks`; `problems` остаётся проекцией задач для прежних клиентов. Миграция `0017` заполняет блоки прежних листков без изменения их задач и шаблона `math-a4-v1`. Шаблоны поддерживаются независимо от номера приложения.

## Кеш TeX и объём на диске

| Данные | Политика по умолчанию |
| --- | --- |
| PDF черновика | Не записывается в дисковый кеш |
| PDF сохранённых материалов | До 128 МиБ, 256 файлов, 7 дней без обращения; LRU |
| ZIP локального сборщика | До 128 МиБ, 2 архивов, 14 дней; LRU |
| Временные файлы задания | До 64 МиБ и 2048 файлов/каталогов, до 20 секунд; удаляются при успехе и ошибке |
| Доверенные ресурсы Tectonic | Подготавливаются установщиком; пользовательские сборки читают их без записи и без сети |
| Картинки материалов | Хранятся в БД как содержимое, не относятся к очищаемому кешу |

Временные каталоги имеют блокировку на время задания. После аварийного завершения следующий запуск удаляет оставленные каталоги старше минуты; активные задания сохраняются. Ссылки и посторонние файлы очистка не обходит. Операции кеша выполняются под межпроцессной блокировкой. Ошибка записи кеша не мешает отдать успешно собранный PDF.

```bash
.venv/bin/python backend/manage.py tex_cache
```

Команда очищает просроченные/лишние сгенерированные файлы и показывает объём PDF, архивов и доверенных ресурсов. Лимиты задаются `PLUSFOLIO_PDF_CACHE_MIB`, `PLUSFOLIO_PDF_CACHE_FILES`, `PLUSFOLIO_PDF_CACHE_DAYS`, `PLUSFOLIO_TEX_ARCHIVE_CACHE_MIB`; нулевые PDF-лимиты отключают хранение PDF. Лимит архива должен вмещать сам пакет сборщика. Один проект ограничен 2 МиБ исходников и 4 МиБ нормализованных PNG; тело проекта — до 8 МиБ, готовый PDF — до 16 МиБ.


Миграция `0018` задаёт прежним листкам начало с 1 и включает все задачи в плюсник. `WorksheetBlock` хранит флажок содержимого, `WorksheetItem` — его проекцию для журнала и аналитики. В журнале `worksheet_position` — исходный напечатанный номер (включая 0), а не порядковый номер оставшегося столбца. Листок со всеми снятыми флажками остаётся доступен из кружка как материал без задач для плюсника.
