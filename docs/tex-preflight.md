# Обязательная проверка TeX перед загрузкой

Робот получает `GET /api/v1/tex/toolchain` и `GET /api/v1/tex/toolchain/archive` с тем же Bearer-токеном. Методы доступны преподавателю и администратору, включая токен только для чтения. Архив не содержит БД, ключей или пользовательских документов: только точный сборщик, шаблон, installer, закреплённые зависимости и подготовленный кэш TeX.

Сохраните `contract_id` из JSON. Распакуйте ZIP в отдельный каталог; сверяйте SHA-256 файлов с `toolchain-manifest.json`. Локальная команда также проверяет полный набор файлов и совпадение `--expected-contract` с актуальным сервисом. Репозиторий иной ревизии, произвольный LaTeX и встроенный компилятор редактора не заменяют этот пакет.

## Подготовка один раз для данного пакета

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-tex.lock
.venv/bin/python scripts/preview_tex.py --prepare --expected-contract <CONTRACT_ID_ИЗ_API>
```

Installer загружает официальный Tectonic **0.17.0** с проверкой закреплённого SHA-256 архива для macOS arm64 / Linux x86_64 / Linux aarch64. В архиве уже есть подготовленные offline-ресурсы, включая шрифты; для пользовательского TeX сеть запрещена. На Linux необходим bubblewrap (`bwrap`), на macOS используется `sandbox-exec`. Если среда не поддерживается, компилятор недоступен, хеш не совпал или sandbox не работает, MUST остановить публикацию и задать дополнительный вопрос о продолжении. Не отключать изоляцию и не заменять компилятор.

## Черновик одной задачи

```json
{
  "kind": "problem",
  "problems": [{
    "title": "",
    "description": "",
    "statement": "<СОГЛАСОВАННОЕ УСЛОВИЕ>",
    "solution": "<СОГЛАСОВАННОЕ РЕШЕНИЕ>",
    "statement_tex": "",
    "solution_tex": ""
  }]
}
```

Для kind=problem заголовок и описание берутся из единственного объекта problems; worksheet используется только при kind=worksheet. Обычные тексты и TeX обрезаются по краям так же, как при сохранении в сервисе. Для существующей задачи передайте её действительный `id`, `title`, обычные тексты, TeX и `attribution` из GET материала. Для новой задачи `id` отсутствует: временные имена `draft-001` нужны только файлам предпросмотра, их нельзя отправлять как UUID в API. Если название новой задачи пусто, служебный заголовок предпросмотра временный; после создания сервис покажет выданный номер. Визуальная проверка содержимого обязательна до POST.

## Сборка

```bash
.venv/bin/python scripts/preview_tex.py --input draft.json --output review-task-001-v1 --expected-contract <CONTRACT_ID_ИЗ_API>
```

Каждая новая редакция получает новый выходной каталог. Команда не загружает настройки приложения, аккаунты или БД и не создаёт задач/листков. Она напрямую вызывает **те же `project_for`, `fragment`, `flatten` и `render_pdf` из `backend/core/documents.py`**, что и сервис. Временный PDF-кэш пустой, поэтому выполняется реальная компиляция обоих вариантов:

- `statement.pdf` — условие без решения;
- `with-solutions.pdf` — условие и решение;
- соответствующие `.tex` и каталоги многофайловых проектов;
- `report.json` — ID пакета, SHA-256 входного JSON, проектов и PDF, версия компилятора и предупреждения сборки.

Статус отчёта `requires_visual_review_and_user_confirmation` НЕ означает согласование. Он требует просмотра и дополнительного вопроса пользователю.

## Что именно повторяется

Основной файл `main.tex` включает `variables.tex` и `template.tex`. Шаблон — **math-a4-v1**, `article`, 11pt, A4, поля 22 мм, DejaVu Serif/Sans, русский язык через polyglossia, amsmath/amssymb/amsthm/enumitem/TikZ. Файлы условий: `tasks/001-<id>.tex`; решений: `solutions/001-<id>.tex`; порядок задают `problems.tex` и `solutions.tex`.

В библиотеке переменные кружка, даты и номера равны «НАЗВАНИЕ КРУЖКА», «ДАТА ВЫДАЧИ», «НОМЕР ЛИСТОЧКА». Их нельзя молча заменять текущей датой или предполагаемым кружком. В отдельном PDF задачи сборщик убирает поля выдачи так же, как сервис. На листе решений используется разрыв страницы и исходная нумерация задач.

Непустой `statement_tex` / `solution_tex` имеет приоритет. Если он пуст, обычный текст экранируется, а однострочные `$...$` сохраняются по правилам `fragment()`. Не нужно самостоятельно повторно экранировать текст или собирать другое окружение. TeX-фрагменты не содержат documentclass, usepackage, begin/end document. Подключённые библиотеки TikZ: calc, angles, quotes, intersections, positioning, arrows.meta, decorations.markings, shapes.geometric, patterns, babel. Дополнительные пакеты не подключаются самовольно.

Команда компилятора: `tectonic -X compile --untrusted --only-cached --keep-logs main.tex`. `tex_worker.py` и `render_pdf` обеспечивают те же ограничения: 20 секунд wall time, 12 секунд CPU, PDF/файл до 16 МиБ, 256 открытых файлов, на Linux адресное пространство до 1 ГиБ. Сеть запрещена; доступны только рабочий каталог, доверенные ресурсы и системные библиотеки/шрифты. Если пользовательский фрагмент требует отсутствующего ресурса, MUST остановиться и обсудить исправление или обновление доверенного пакета.

## Визуальное согласование

Робот MUST открыть оба PDF, отрисовать и просмотреть **каждую страницу**, а не ограничиваться кодом возврата, размером файла или извлечённым текстом. Проверить русский текст, все формулы и индексы, знаки неравенств, переносы, нумерацию, поля, разрывы страниц, TikZ и подписи. Отдельно проверить `warnings` в отчёте: пропавшие символы и переполнения не игнорировать. Проблемные предупреждения исправить; допустимое предупреждение объяснить пользователю.

Показать пользователю оба PDF (или предпросмотр всех страниц) и задать дополнительный вопрос **только по текущей задаче**. После исправления пересобрать и спросить снова. Согласование фиксируется для конкретных `toolchain_id`, `input_sha256` и `pdf_sha256`. Любая правка входа или изменение пакета требует новой сборки и нового согласования вёрстки. Успешная компиляция не доказывает правильность решения.

## Финальный листок

После последовательного согласования всех задач и выбора названия/описания/тем/тегов подготовить `kind=worksheet`, `worksheet={title,description,template_version:"math-a4-v1"}` и `problems` как массив полных данных уже выбранных задач в согласованном порядке. Выполнить ту же команду в новом каталоге, проверить и согласовать оба PDF целого листка до POST создания листка.

Этот JSON предназначен только локальному предпросмотру. В POST /api/v1/materials/worksheet массив `problems` содержит **UUID**, а не объекты черновика; `kind` и поля отчёта в API не передаются. В POST задачи передаются ровно согласованные обычные тексты и TeX, использованные при предпросмотре. После получения ID сравнить серверный PDF с согласованным макетом. Байтовое равенство разных PDF не требуется: служебные ID и PDF-метаданные могут отличаться.
