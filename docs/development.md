# Разработка и проверка Plusfolio

Практическое руководство по текущей реализации. Начальная точка — [architecture.md](architecture.md); поведение пользователя описывает генерируемая справка сайта, HTTP-контракт — OpenAPI. Перед изменением проверить текущие `git status`, локальные инструкции и затронутые модули. Чужие незакоммиченные изменения сохранять.

## Источники истины

| Вопрос | Где проверять |
| --- | --- |
| Роли и объектный доступ | `backend/core/services.py`, `people.py`, их tests; frontend `access.ts` только управляет видимостью UI |
| Схема и ограничения | `backend/core/models.py`, миграции; не проектные диаграммы из старых версий |
| Доступ к решению | `solutions_for` / `visible_solution_ids`, затем общие сериализаторы, поиск и PDF |
| Метрики и фильтры | `analytics.py`, `filters.py`, `journal.py`, `frontend/src/journalView.ts`; [analytics.md](analytics.md) |
| Листки/редакции/выдачи | `worksheets.py`, `issue_updates.py`, `content.py`; [worksheet-builder.md](worksheet-builder.md) |
| HTTP | `api.py`, `api_v1.py`, `api_reference.py`; справка строится из того же описания, что OpenAPI |
| Сборка TeX | `documents.py`, `tex_*`, `scripts/setup_tex.py`, `preview_tex.py`; `SOURCE_FILES` и receipt |
| Конфигурация | `backend/config/settings.py`, `compose.yml`, выбранные overlays, `scripts/server_host.py`/`server_storage.py` |
| Версии зависимостей | `requirements*.lock`, `frontend/package-lock.json`, закреплённые downloader manifests |
| Релиз | `release.json`, `scripts/release.py`, `docs/releases/`; [server-deploy.md](server-deploy.md) |

Документы product/data-model могут содержать явно отмеченные планы. При противоречии реализация и регрессионные тесты определяют текущее поведение; сначала выяснить инвариант, затем поправить и код, и документацию. Нельзя незаметно превращать проектную возможность в обещание работающей функции.

## Правила изменений

1. Воспроизвести проблему и определить путь запроса/жизненный цикл объекта. Для оптимизации снять исходный размер/число запросов/аллоцирование на понятном наборе данных.
2. Найти существующую политику, builder или компонент. Использовать его; выделять новый модуль только для связной ответственности или реального повторного использования.
3. Ограничить работу до загрузки payload: размер, число объектов, очередь, время, число параллельных операций. После исключений освободить слот, процесс, файлы и дескрипторы.
4. Не смешивать изменение прав/предметной семантики с уборкой. Не удалять queryset-фильтры ради скорости, не кэшировать решения авторизации между пользователями.
5. Сохранить удобочитаемые имена и явные типы границ. Комментарий объясняет причину или инвариант. Не добавлять универсальные обёртки, одноразовые классы и тесты, повторяющие строку реализации.
6. Общие размеры/лимиты имеют один источник и семантическое имя. Контрактные значения (версия Tectonic, размерность модели, роли, виды блоков) уместны как константы. Env/config нужен для эксплуатационной настройки, а не для каждого литерала.
7. Сначала целевые проверки, затем один полный прогон после завершения независимых правок. После уже успешного прогона повторять только то, что затронули новые изменения или найденный риск.

## База и массовые операции

- Для однократного большого чтения использовать `values_list(...).iterator(chunk_size=...)` или `only(...).iterator(...)`; обычная итерация QuerySet сохраняет результат целиком.
- Для массовой записи держать в Python только текущую партию. `bulk_create(batch_size=...)` сам по себе не ограничивает заранее созданный список моделей.
- Сохранять транзакцию, уникальность, assigned_at и идемпотентность. При параллельных операциях проверять версии/блокировки. Не повторять поиск всех существующих назначений при каждом добавлении школьника.
- Избегать запросов в ячейке/строке сериализации. Узкие проекции и Prefetch согласовывать с тем, какие свойства потом читаются: отложенное поле может вернуть N+1.
- Оптимизация групп получателей не меняет дедупликацию школьник × задача и область видимости. Локальный tracemalloc не измеряет всю память БД и контейнера.

## Браузер и жизненный цикл

Геометрия плюсника имеет один источник в CSS custom properties контейнера; JSX передаёт только количества столбцов. Не добавлять параллельные фиксированные ширины в inline-стили. `materialDetail.ts` ограничивает чтение карточки одним запросом и не открывает ответ после отмены. `worksheetCopy.ts` позволяет принятому POST завершиться, но лишает прежний preview права менять интерфейс после смены контекста; это не откат серверного действия.

Отменять запрос в cleanup эффекта при смене аккаунта, фильтра, маршрута и размонтировании. Нужна и защита от позднего ответа, если транспорт не может гарантировать отмену. Не показывать abort как пользовательскую ошибку.

Долгоживущий ref/Map должен иметь явную политику вытеснения. В списке выбора достаточно текущих options и выбранных элементов; история всех поисков не нужна. PDF.js освобождает loading/render tasks, документ и canvas. Новые обработчики таймеров и событий должны иметь cleanup.

Проверять UI на реальных разрешённых ролях, узком окне, длинном имени/ID, пустом результате и повторном действии. Для журнала проверять ширину ячейки, центр SVG, подсказки, исходную нумерацию, фильтры, состояние сохранения и позицию прокрутки. Снимок должен показывать результат; изменение на сайте не подтверждается только typecheck.

## Быстрые проверки

Команды выполняются из корня проекта. Используйте отдельный `PLUSFOLIO_LOCAL_DIR` для тестов; не тестируйте миграции или очистку на рабочем каталоге данных.

```bash
export PLUSFOLIO_LOCAL_DIR="$(mktemp -d /tmp/plusfolio-check.XXXXXXXX)"
export POSTGRES_HOST=
python3 scripts/release.py --check
.venv/bin/python backend/manage.py check
.venv/bin/python backend/manage.py makemigrations --check --dry-run
.venv/bin/python backend/manage.py test core.test_release core.test_documentation --noinput
(cd frontend && npm test && npm run build)
PYTHONPATH=deploy .venv/bin/python -m unittest deploy.test_shared_host deploy.test_capacity deploy.test_cloud_deploy.ImageTests deploy.test_cloud_deploy.StorageTests deploy.test_downloads
git diff --check
```

Для затронутого предметного модуля сначала запустить его тесты, затем `manage.py test core --noinput` в отдельной SQLite-БД. Часть конкурентных и поисковых тестов требует PostgreSQL: skip в SQLite не является их успешным прохождением. S3-тестам нужны server-зависимости; тесты серверных утилит с замоканным Docker не являются проверкой реального контейнера.

`verify.yml` собирает Linux-стек, проверяет HTTPS/SMTP/поиск/TeX, PostgreSQL и резервирование. Docker integration запускается из отдельного чистого checkout через `deploy/check_server.py`, со своим Compose project. Не используйте каталог действующего экземпляра. Если среда недоступна, сохранить это ограничение в отчёте, а не приписывать CI локальный успех.

## TeX: особые проверки

После правки `SOURCE_FILES`, preparation inputs, шаблонов или ресурсов выполнить trusted setup, получить новый contract и ZIP, распаковать в новый каталог и дважды запустить `--prepare --expected-contract ...`. Хеши после подготовки не меняются. Затем собрать обе версии PDF, просмотреть все страницы и warnings. Изменение только release metadata или журнала не меняет TeX-contract, если все отобранные файлы совпали побайтово.

Фикстура с временным LOCAL_DIR должна явно переопределять `TEX_RESOURCE_DIR`: серверный образ задаёт путь immutable-ресурсов, и он не должен подменять тестовые файлы. Ссылки на live cache нельзя удалять вместе с lease-каталогом. Пользовательский TeX не получает сеть или запись в доверенные ресурсы.

## Измерения и отчёт

Отделять retained allocations от временного пика, Python heap от RSS/cgroup memory и файлового кэша. Для диска проверять остатки после успеха, ошибки, прерывания и нескольких версий, а не только размер одного ZIP. Для скорости считать реальные обращения/объекты и время с прогретым/холодным кэшем.

В `docs/benchmarks/` сохранять сценарий, платформу, размер данных, команды, результаты, ограничения и provenance. Не включать токены, содержимое пользовательских материалов и контактные данные. Большие промежуточные файлы хранить вне Git и удалять после проверки. Стабилизация достигнута, когда повторный независимый проход не находит конкретных дефектов в проверенной области; это не доказательство отсутствия всех возможных ошибок.

## Документация и релиз

Изменились поля/доступ — обновить OpenAPI и ролевую справку. Изменились пути/ресурсы/ограничения — обновить архитектуру, TeX/deploy/backup guides. Изменились рабочие модули — обновить таблицу выше. Архивы старых релизов и отчёты измерений не переписывать под новое поведение.

Версию менять штатным `release.py --set`, не редактировать npm mirrors независимо. Новый локальный commit/tag и публикация — отдельные действия; опубликованный тег неизменяем. Перед обновлением сервера необходимы свежая копия, проверка миграций и план восстановления. Не выполнять глобальную очистку Docker/диска ради освобождения места своего проекта.
