# Plusfolio

Первая релизная версия — **1.0.0**, тег `v1.0.0`. Источник номера и статуса — [`release.json`](release.json); [история изменений](CHANGELOG.md).

```bash
python3 scripts/release.py --check   # версия исходников и согласованность npm-файлов
python3 scripts/server.py version   # версия образа в работающем серверном экземпляре
```

Используем [SemVer](https://semver.org/): PATCH — совместимые исправления, MINOR — совместимые возможности, MAJOR — несовместимые изменения публичного контракта. `/api/v1`, версии миграций, модель поиска и шаблон TeX версионируются независимо. Для следующей версии: `python3 scripts/release.py --set 1.0.1 --status development`; перед её выпуском — тот же номер с `--status released`, проверки и отдельный неизменяемый Git-тег `v<версия>`. После выпуска содержимое тега не меняется. Ветка `main` между выпусками может содержать незавершённые изменения.

Локальная функциональная демка сервиса для математических кружков: задачи и листки, несколько преподавателей, журнал сдачи, общая решённость между кружками и аналитика. Все демонстрационные аккаунты и материалы вымышленные.

## Сервер: установка одной командой

```bash
bash scripts/install_server.sh
```

Из уже склонированной папки проекта установщик проверит готовые Docker 28+, Compose v2, Buildx и Python, запросит адрес сайта, первого администратора, SMTP и локальный порт. Он создаст собственные ключи/сети/хранилища и запустит сервис только на `127.0.0.1:18080`, с лимитами ресурсов и автоматической очисткой зашифрованных бэкапов. Docker и пакеты хоста не устанавливаются и не обновляются. HTTPS подключается через существующий прокси администратора сервера. Демо-аккаунтов нет. Нужны сервер в России, домен и SMTP-доступ для приглашений.

[Пошаговая установка, обновление, резервные копии и проверка из чистой копии](docs/server-deploy.md).

## Запуск

Нужны Python 3.12+ и Node.js 22.13+ с npm. Проверено на Python 3.14 и Node.js 26. Репозиторий находится в `/Users/arsoz/Desktop/my_stuff/pet/Plusfolio`.

```bash
cd /Users/arsoz/Desktop/my_stuff/pet/Plusfolio
bash scripts/run_demo.sh
```

Скрипт создаёт `.venv`, устанавливает зависимости из lock-файлов, собирает интерфейс, применяет миграции и добавляет демоданные только при первом запуске. Затем открывайте [http://127.0.0.1:8000](http://127.0.0.1:8000). Остановка — Ctrl+C; изменения сохраняются. Для установки зависимостей и первого прогрева Tectonic нужен интернет, после установки и сборки демка работает локально без внешних сервисов. Компилятор устанавливается автоматически при первом запуске; повторная подготовка — `.venv/bin/python scripts/setup_tex.py`. На Linux дополнительно нужен системный `bubblewrap` (`bwrap`).

Django/DRF и React/TypeScript работают через один локальный сервер; SQLite хранится в `.local/demo.sqlite3`. Сервис слушает только 127.0.0.1. Этот скрипт всегда выбирает локальную SQLite, даже если в shell есть параметры PostgreSQL. Для рабочего размещения выбран PostgreSQL, см. [архитектуру](docs/architecture.md).

## Вход и проверка ролей

На странице входа есть кнопки демо-профилей. После входа переключение находится в отдельной кнопке «Демо-профили» внизу слева. Имя/аватар и пункт «Личный кабинет» открывают страницу аккаунта с личными данными, сводкой по назначенным ролям, сменой имени/пароля и выходом. Это переключение вымышленных аккаунтов, а не изменение роли текущего пользователя.

Общий демонстрационный пароль: **`PlusfolioDemo2026!`**.

| Аккаунт | Возможности |
| --- | --- |
| `admin@plusfolio.example` | Все кружки, создание пустого кружка, назначение преподавателей, роли и дерево тем |
| `teacher@plusfolio.example` | Два кружка, журнал, состав, материалы, выдачи и приглашения |
| `mentor@plusfolio.example` | Второй преподаватель общего кружка; также ведёт другой кружок |
| `student@plusfolio.example` | Журнал всего своего кружка; решения после открытия преподавателем; аналитика только по себе |
| `analyst@plusfolio.example` | Чтение кружков по разрешённому тегу, включая решения |
| `multi@plusfolio.example` | Учитель + аналитик, области прав объединяются без расширения каждой роли |

В наборе три кружка, 12 школьников, 8 задач и 3 листка. Две группы пересекаются по школьникам и задачам — можно проверить глобальные отметки и независимый разбор. В демке не вводите реальные персональные данные: сначала проверяем механику на вымышленных адресах и именах.

## Что попробовать

1. Преподавателем открыть «Математическую мастерскую», поменять решение и разбор, перезагрузить страницу.
2. Школьником открыть тот же журнал: строки всех участников видны, редактирование недоступно; решения видны только у разобранных задач с включённым показом. В аналитике только личные результаты. В разделе «Мои задачи» — все полученные задачи без дублей и все выдачи листков. Открытое хотя бы в одном действующем кружке решение доступно и здесь.
3. Аналитиком открыть разрешённый кружок и раскрыть решение. У профиля учитель + аналитик право редактирования зависит от преподавания конкретного кружка.
4. Администратор может открыть «Теги» и добавить тег в справочник задач, листков или кружков. Создать задачу с несколькими темами и готовыми тегами, собрать листок, выдать кружку. Опубликованное исправляется созданием копии; повторная выдача того же листка запрещена.
5. В журнале переключить «Один листок / Выбранные / Все листки». При нескольких листках задачи разбиты на блоки. Выгрузить текущий срез кнопкой «Выгрузить»: Excel (.xlsx) по умолчанию или TSV; учитываются выбранные листки и поиск школьника.
6. Отправить приглашение на вымышленный email, открыть «Приглашения → Открыть письма». Письма остаются на этом компьютере. Новый адрес становится участником после принятия; у зарегистрированного получателя добавляется роль после входа под его email.
7. Администратором открыть «Пользователи и роли»: искать по ФИО/email, выбрать несколько ролей, состояний и годов выпуска. На вкладке школьников кружка — «Добавить школьника»: поиск по ФИО с классом и подсказкой email или прежнее добавление по точному email.
8. Открыть PDF листка в библиотеке: в шапке будут заглушки. Открыть тот же листок в кружке: подставятся название кружка, дата и стабильный номер выдачи. В предпросмотре можно включить доступные решения; преподаватель скачивает единый TeX или ZIP многофайлового проекта. В редакторе задачи необязательные TeX-поля принимают TikZ; без них используется обычный текст.
9. Добавить зарегистрированного школьника по email: он автоматически получит все прошлые листки. Выбытие сохраняет назначения и решения; возврат не создаёт дубли.

Полный сценарий и границы реализации — [локальная демка и этапы выпуска](docs/release-roadmap.md). Это рабочий локальный вертикальный срез; серверный запуск с PostgreSQL и SMTP описан выше. Восстановление забытого пароля по email пока не реализовано; в личном кабинете есть смена известного пароля.

Сервер поддерживает отдельные диски PostgreSQL/архивов, внешнюю PostgreSQL с TLS, зашифрованные S3-бэкапы и готовые образы из Cloud Registry. [Профиль Yandex Cloud, обновление и восстановление](docs/server-deploy.md#yandex-cloud-и-независимое-размещение). [Нагрузочный пилот Linux/PostgreSQL и расчёт хранения](docs/pilot-capacity.md).

```bash

```

Автоматические проверки охватывают границы ролей, отсутствие закрытых решений у школьника и показ разрешённых решений, личную аналитику, несколько ролей и преподавателей, глобальные решения, независимый разбор, конфликты версий, позднее вступление, историю участия, уникальную выдачу, неизменяемость, темы/теги, инвайты и CSRF. ## Полные резервные копии демки

```bash
.venv/bin/python backend/manage.py backup_demo
.venv/bin/python backend/manage.py restore_demo .local/backups/ИМЯ_АРХИВА.pfb
.venv/bin/python backend/manage.py restore_demo .local/backups/ИМЯ_АРХИВА.pfb --into /private/tmp/plusfolio-restored
```

Первая команда сохраняет согласованный снимок SQLite, исходники, миграции, lock-файлы, frontend-сборку, каталог тем, документы, установленный Tectonic с прогретым кэшем пакетов/шрифтов и ключ приложения в зашифрованный комплект. Вторая проверяет целостность без изменения БД. Третья восстанавливает в **новую** папку, отзывает восстановленные сессии и инвайты, отменяет почтовую очередь. Существующая папка не перезаписывается. Для запуска восстановленной демки потребуются Python/Node и зависимости из lock-файлов; компилятор и его кэш восстанавливаются для той же ОС/архитектуры. На другой платформе выполните `scripts/setup_tex.py`; автономные контейнерные образы добавляются к production-комплекту.

Ключ `.local/backup.key` не входит в архив — сохраните его отдельной защищённой копией. Для перенесённого архива укажите `--key /путь/к/backup.key`. Не публикуйте `.local` и ключи в Git. Автоматические внешние копии и PostgreSQL PITR для размещённой версии пока спроектированы в [плане резервирования](docs/backups.md).

## Каталог тем problems.ru

Исходный снимок и следы происхождения находятся в `data/problems_topics.json`; схема — рядом. `metadata.complete` показывает завершённость обхода математического дерева. До завершения интерфейс показывает предупреждение. Задачи и решения с problems.ru не импортируются.

Продолжение или обновление каталога с локальным кэшем:

```bash
python3 scripts/fetch_topics.py --max-fetches 0
.venv/bin/python backend/manage.py import_topics data/problems_topics.json
```

Сборщик соблюдает robots.txt и задержку не меньше 20 секунд, пишет снимок после каждой страницы. Остановленный обход можно продолжить; полный повтор использует кэш. Для повторной сборки из уже загруженного кэша есть `--offline`. Импорт добавляет отсутствующие узлы со стабильными ID и сохраняет правки существующих тем администратора. «Прочее» автоматически создаётся под каждым обычным узлом и корнем, остаётся терминальной и последней в разделе.

В плюснике редактор может включить «Показать решение» для разобранной задачи. Настройка действует отдельно в каждом кружке. Школьник увидит решение по клику на задачу; при снятии разбора показ автоматически выключается.

Первое получение роли школьника существующим аккаунтом также требует этих данных. Прежние записи автоматически не переименовываются: в личном кабинете школьника показывается подсказка заполнить ФИО и год. При последующем редактировании этих данных они остаются обязательными.

## Личные листки и публикация

В «Листках» карточка открывает отдельную страницу с автором, версией, задачами и PDF/TeX/ZIP. «Мои листки» содержит личные версии; у администратора дополнительно есть раздел всех авторов. Любой читатель листка может сохранить себе независимую личную копию и менять её название, описание, темы, теги, состав и порядок задач. Для школьника доступен раздел «Личные листки» рядом с «Моими задачами»; общие банки задач и дерево тем ему не открываются.

Личные листки видят автор и администратор; при выдаче участники кружка получают именно выданную версию. Только автор редактирует оригинал или свою копию, только администратор публикует версию в общей библиотеке. Правки после публикации остаются личными до повторной публикации; библиотека продолжает показывать прежнюю опубликованную версию.

Каждое сохранение создаёт неизменяемую версию. Уже выданные листки, задачи в журнале, назначения, PDF и TeX не меняются. Повторно выдать тот же листок в тот же кружок нельзя даже после редактирования; независимую копию можно. Старые листки при миграции сохраняют автора, ссылки, публикацию и все выдачи. Проверки: `.venv/bin/python backend/manage.py test core.test_worksheets`.

## Импорт задач и необязательные названия

В локальную демку можно загрузить 500 текстовых задач из семи разделов problems.ru: условия, ответы и доступные решения, исходные номера и темы. Названия задач необязательны: в интерфейсе используются постоянные номера, а все связи остаются по UUID. Импорт повторяемый, опубликованные задачи не перезаписываются. Инструкции и ограничения подборки — [в описании импорта](docs/problems-import.md).


### ID сущностей

Внутренние связи сохраняют прежние первичные ключи (UUID либо числовые ID). Для интерфейса и точного поиска используются постоянные ID с независимой нумерацией по типам: `U-…` — аккаунт, `S-…` — школьник, `T-…` — преподаватель, `C-…` — кружок, `P-…` — задача, `W-…` — листок, `TOP-…` — тема, `TAG-…` — тег, `INV-…` — приглашение, `ISS-…` — выдача листка. Номера выделяет база данных; UUID-сущности имеют отдельные таблицы счётчиков и уникальный индекс. Существующие данные получают номера миграцией 0009, номера задач из 0008 сохраняются.

Введите такой ID в обычное поле поиска нужного раздела или формы выбора. Префикс не зависит от регистра; `P-0012` и `P-12` равнозначны. В поиске школьника принимаются `S-…` и `U-…`, а число без префикса означает ID школьника; в списке пользователей число означает ID аккаунта. Кнопки рядом с ID в карточках и личном кабинете копируют их в буфер. Полный внутренний UUID также можно искать в соответствующих каталогах.

`W-…` относится к логическому листку и остаётся общим для его версий. Копия получает новый ID. Номер выдачи внутри кружка и `ISS-…` хранятся отдельно. Номер задачи на problems.ru также остаётся отдельным: `P-…` всегда ищет локальную задачу Plusfolio. Поиск выполняется внутри доступной пользователю области и не раскрывает чужие личные листки или закрытые решения.

## Поиск задач на CPU

`./scripts/run_demo.sh` теперь также запускает локальную ONNX INT8 модель E5 и фоновую индексацию. В банке, «Моих задачах», подборе задач в листок и форме создания доступны поиск по условиям/решениям и подсказки совпадений. Закрытые решения не участвуют в поиске школьника. При недоступной модели остаётся текстовый поиск.

[Запуск, Docker, PostgreSQL, API, бэкапы и повторяемые замеры](docs/problem-search.md).

Поиск названий и описаний кружков/листков, метаданных задач и путей тем использует ту же CPU-модель и существующий индексатор. API: `GET /api/v1/catalogue-search`; задачи — `problem-search` с `field=metadata` или массивом `fields`. После прямых массовых правок БД: `.venv/bin/python backend/manage.py index_problem_search --rebuild`. Подробнее: `docs/problem-search.md` и раздел документации «Поиск названий и описаний по смыслу».
